0. 2026년 꼭 알아야 할 변경점

블로그·영상 강의는 대부분 예전 방식을 알려줍니다. 아래 4가지는 최신 공식 자료 기준이니 옛 튜토리얼과 다르면 이쪽을 따르세요.

① API 키 이름이 바뀌었어요. 예전 anon / service_role 대신 sb_publishable_...(공개용) / sb_secret_...(서버 전용)을 씁니다. 공식 changelog는 레거시 키 삭제 시점을 “2026년 말(확정 아님)”로 안내했으니, 예전 키로 만든 프로젝트는 미리 옮겨 두세요.

② 새 테이블이 자동으로 API에 노출되지 않아요. 공식 changelog(2026-04-28 공지)에 따르면 새 프로젝트는 2026-05-30부터, 기존 프로젝트는 2026-10-30부터 public 스키마의 새 테이블에 GRANT를 직접 줘야 supabase-js로 보입니다. 안 주면 42501 permission denied 에러가 납니다. 기존 테이블은 그대로 동작합니다. (본인 프로젝트에 적용됐는지는 대시보드/공지 메일에서 확인하세요.)

③ 무료 플랜 한도(2026년 요금 페이지 기준). 프로젝트 2개, DB 500MB, 월 활성 사용자 50,000명, 파일 저장소 1GB, 송신 5GB, 그리고 1주일 동안 활동이 없으면 자동 일시정지. 포트폴리오용으로 충분하지만, 면접 직전에 프로젝트가 잠들어 있지 않은지 꼭 확인하세요. 유료 Pro는 월 $25부터입니다.

④ 서버 쪽 로그인 확인은 getClaims()를 권장하는 흐름입니다. 브라우저만 쓰는 입문 단계에서는 getSession()/onAuthStateChange로 충분하지만, “권한 판단의 근거”로는 쓰면 안 된다는 것만 기억하세요.

1. Supabase가 뭔가요?

식당에 비유해 볼게요. 프론트엔드는 홀(손님이 보는 화면), 백엔드는 주방(재료 보관·조리·계산)입니다. 직접 주방을 지으려면 서버, DB, 로그인 시스템이 필요하죠. Supabase는 “이미 지어진 주방”을 빌려 주는 서비스(BaaS)입니다.

기능역할프론트에서 쓰는 모습
Database진짜 PostgreSQL(표 형태 데이터 저장)supabase.from('todos').select()
Auth회원가입·로그인·소셜 로그인supabase.auth.signInWithPassword()
Storage이미지·파일 저장supabase.storage.from('avatars').upload()
Realtime데이터 변경을 실시간 수신supabase.channel('room').on(...)
Edge Functions비밀 키가 필요한 서버 코드supabase.functions.invoke()

핵심 질문: “브라우저에서 DB를 직접 부르면 아무나 내 데이터를 보는 거 아냐?” → 그래서 RLS(행 단위 보안)와 GRANT(테이블 접근 권한)가 있습니다. 이 가이드북의 절반은 이 두 가지를 이해하는 데 씁니다.

2. 프로젝트 만들기 (설정 방법)

  1. supabase.com 접속 → Start your project → GitHub 계정으로 로그인.
  2. 조직(Organization)을 만들고 New project 클릭.
  3. 프로젝트 이름 입력, Database Password는 비밀번호 관리자에 저장(나중에 직접 쓸 일은 적지만 분실하면 재설정해야 함).
  4. Region은 한국에서 가까운 Northeast Asia (Seoul) 선택.
  5. Data API 관련 옵션에 Automatically expose new tables 체크박스가 보이면, 입문 단계에서는 체크 해제(권장 기본값) 상태로 두고 이 가이드북의 GRANT 습관을 익히는 편이 안전합니다.
  6. 생성에 1~2분 걸립니다. 완료되면 상단 Connect 버튼에서 Project URL과 Publishable key를 확인합니다.

※ 대시보드 메뉴 이름·위치는 수시로 바뀝니다. 이름이 조금 달라도 같은 기능을 찾으면 됩니다.

3. API 키 이해하기

키접두사어디에 쓰나브라우저에 넣어도?
Publishablesb_publishable_React 등 클라이언트 코드가능 (권한은 RLS가 통제)
Secretsb_secret_서버, Edge Function, 배치 작업절대 금지 (RLS를 우회)
(레거시) anon / service_role긴 JWT 문자열각각 publishable / secret의 구버전anon만 가능

키 위치: 대시보드 Settings → API Keys. 로그인 전 요청은 anon 역할, 로그인 후에는 authenticated 역할로 DB에 접근하며, 이 역할이 뒤의 GRANT/RLS 판단 기준이 됩니다.

실무에서도 통하는 필수 습관: secret 키를 GitHub에 올리면 즉시 폐기(재발급)해야 합니다. 프론트 코드에는 URL + publishable 키만 넣으세요.

4. 첫 테이블 + 권한 SQL

대시보드 왼쪽 SQL Editor에 붙여 넣고 Run. “내 할 일(todos)” 테이블입니다.

-- 1) 테이블 만들기
create table public.todos (
  id bigint primary key generated always as identity,
  user_id uuid not null default auth.uid() references auth.users(id),
  title text not null,
  done boolean not null default false,
  created_at timestamptz not null default now()
);

-- 2) RLS 켜기 (켜는 순간 정책이 없으면 아무도 못 읽음)
alter table public.todos enable row level security;

-- 3) 2026년 방식: 로그인한 사용자에게만 테이블 권한 부여
grant select, insert, update, delete on public.todos to authenticated;

-- 4) 정책: 내 행만 읽고 쓰기
create policy "내 할 일만" on public.todos
  for all to authenticated
  using ((select auth.uid()) = user_id)
  with check ((select auth.uid()) = user_id);

한 줄 요약: GRANT = “이 역할이 테이블 문을 열 수 있나?” / RLS 정책 = “열 수 있다면 어떤 행까지 보이나?” 두 관문을 모두 통과해야 데이터가 나옵니다.

5. React(Vite) 연결

npm create vite@latest my-app -- --template react
cd my-app
npm install @supabase/supabase-js

프로젝트 루트에 .env.local 파일을 만듭니다. (.gitignore에 포함되어 있는지 확인!)

VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxx

src/lib/supabaseClient.js:

import { createClient } from '@supabase/supabase-js'

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY
)

데이터를 화면에 띄우는 최소 예제(App.jsx):

import { useEffect, useState } from 'react'
import { supabase } from './lib/supabaseClient'

export default function App() {
  const [todos, setTodos] = useState([])
  const [error, setError] = useState(null)

  useEffect(() => {
    supabase.from('todos').select('*').order('id').then(({ data, error }) => {
      if (error) setError(error.message)
      else setTodos(data)
    })
  }, [])

  if (error) return <p>에러: {error}</p>
  return <ul>{todos.map(t => <li key={t.id}>{t.title}</li>)}</ul>
}

npm run dev 후 localhost:5173. 로그인 전이라면 빈 목록이 정상입니다(다음 장에서 로그인 추가).

6. CRUD 치트시트

supabase-js는 항상 { data, error }를 돌려줍니다. 예외를 던지지 않으니 error를 꼭 확인하세요.

하고 싶은 일코드
조회.from('todos').select('*')
조건·정렬·개수.eq('done', false).order('id', { ascending: false }).limit(10)
추가.insert({ title: '공부하기' }).select()
수정.update({ done: true }).eq('id', 1).select()
삭제.delete().eq('id', 1).select()

수정·삭제에 .eq() 같은 조건이 없으면 “전체 삭제” 사고를 막기 위해 거절됩니다. 또한 RLS 때문에 내 행이 아니면 에러 없이 0건 처리될 수 있다는 점이 입문자가 가장 헷갈리는 부분입니다.

7. 로그인(Auth)

// 회원가입
const { data, error } = await supabase.auth.signUp({ email, password })

// 로그인
const { error } = await supabase.auth.signInWithPassword({ email, password })

// 로그아웃
await supabase.auth.signOut()

// 로그인 상태 구독 (React useEffect 안에서)
const { data: { subscription } } = supabase.auth.onAuthStateChange((event, session) => {
  setUser(session?.user ?? null)
})
return () => subscription.unsubscribe()
실습 팁: 이메일 인증이 기본으로 켜져 있어 가입 직후 로그인이 안 될 수 있습니다. 대시보드 Authentication 설정에서 연습용으로만 인증을 끄거나, 인증 메일을 확인하세요. 기본 메일 발송은 시간당 횟수 제한이 매우 낮은 것으로 알려져 있어(약 2통/시간, 변동 가능) 연습 중 429 오류가 나면 이 때문일 수 있고, 실서비스는 별도 SMTP 연결이 필요합니다.
